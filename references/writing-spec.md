# 写作与版式规范

在创建新稿、实质改写或统一版式时读取。目录：结构与例题；样式参数；数学；提示框；图表；语言与数据；来源。只改个别内容时使用相应部分，不扩大任务。

## 1. 结构与例题

写作前列出必要的小节及每节要让读者理解或完成的事，核对符号和例题输入。通常每节 0.5–3 页，标题最多 4 级、不跳级；只存在一个子节时考虑并回父节。不要为凑齐骨架给短通知、简历或术语条目添加例题。

| 类型 | 推荐顺序 |
|---|---|
| 概念 | 为什么需要 → 定义与符号 → 直观解释 → 性质 → 数值例子 → 易错 → 要点 |
| 方法 | 输入/输出/场景 → 核心思路 → 编号步骤 → 前提与代价 → 完整例子 → 易错 → 要点 |
| 例题 | 条件与目标 → 方法/公式 → 分步计算 → 结果 → 代回或量级检查 |
| 对比 | 一句话区别 → 3–5 个维度的短表 → 各自适用场景 → 误解 → 要点 |
| 结果 | 带关键数值的结论 → 条件 → 图表/数据证据 → 误差与局限 → 要点 |

- 开头用 1–3 句说明动机，避免“接下来介绍”“众所周知”。
- 一段一个意思，通常 3–6 行；超过 8 行检查是否能拆。步骤用有序列表，性质用并列列表，论断与理由用段落。
- 例题通常作为所属概念下一级，采用“例 2.1”一类随章节编号的名称；每例给出输入、过程、结果和验算。
- 要点用 2–3 条可复述的结论，不写“本节介绍了……”。
- 原资料有误时保留原陈述的位置与出处，说明正确结论、适用条件及反例/推导，不只写“课件错了”。不将某份旧讲义中的错误推定为所有资料都有的问题。

## 2. 页面与样式

无其他明确模板时：A4，上下页边距 2.2–2.5 cm、左右 2.2–3.0 cm，页眉页脚距边界 1.2–1.5 cm。需要装订才增加装订空间。

西文/数字 Arial，中文宋体（SimSun），原生公式 Cambria Math。代码块可用 Consolas。字体是本技能的默认偏好，不能因此破坏用户指定模板或声称所有机器都必然有这些字体。

| 命名样式 | 字号 pt | 段前/后 pt | 行距 | 其他 |
|---|---:|---|---|---|
| 正文 | 10.5 | 0 / 6 | 1.3 | 无首行缩进；孤行控制 |
| 标题 1 | 16 | 18 / 8 | 1.2 | 粗体；与下段同页 |
| 标题 2 | 13.5 | 12 / 6 | 1.2 | 粗体；与下段同页 |
| 标题 3 | 11.5 | 10 / 4 | 1.2 | 粗体；与下段同页 |
| 标题 4（必要时） | 10.5–11 | 8 / 3 | 1.2 | 粗体；与下段同页 |
| 题注 | 9 | 3 / 6 | 1.0 | 统一对齐 |
| 表格文字 | 9–10 | 0 / 0 | 1.0 | 不用固定行高裁内容 |
| 引用/说明 | 9.5 | 4 / 6 | 1.2 | 左右缩进 0.5 cm；灰色 |
| 代码 | 9–9.5 | 0 / 0 | 1.0 | 等宽；浅灰底纹 |
| 三类提示 | 10.5 | 4 / 4 | 1.3 | 左右缩进 0.3 cm；底纹/左框 |

正文也可统一用 12 pt。中文正式稿如选择首行缩进 2 字符，段后用 0–3 pt；不要同时使用大段距和 2 字符缩进。

- 用段落和字符样式控制重复格式，关闭自动更新；主题的标题、正文也设为 Arial / 宋体。检查标题中的英文不能误用中文字体。
- 旧稿先完成修改清点，再清理确认无语义的直接格式；不要全选后清掉用户颜色、标记或数学字体。
- 章节用链接标题样式的多级列表，编号后统一空格。图表用题注/SEQ 域，交叉引用用引用域；不要同时手打同一套自动编号。
- 公式需要引用时采用一致的右对齐编号；仅输入 `#(2.1)` 不能代替自动编号/交叉引用机制，需检查实际域和更新结果。
- 页脚使用 PAGE / NUMPAGES 域，默认“第 X 页 / 共 Y 页”；页眉短写文档名/章节，9 pt、灰色。已有封面可设首页不同，不为短文档额外造封面。
- 10 页左右及以上建议自动目录，3 页以下通常不用。用分页符/必要的分节符控制页面，不靠空段落和空格挤位置。

## 3. 数学表达

所有方程、等式、不等式和数学公式都必须采用可编辑的 Word 原生公式（OMML），覆盖行内短式、独立公式及表格中的公式。简单程度、长度和是否含特殊符号均不能成为使用普通文本的理由。

- `a = b`、`x + y = 3`、`F = ma` 等简单式子也必须是原生公式，不再使用“出现任意两类数学结构才转为公式”的门槛。
- 分式、上下标、矩阵、求和、积分、根号和范数使用真实数学结构；矩阵用真实行列和可伸缩括号。仅将线性源码放进数学容器不算完成排版。
- 中文解释留在正文，不把整句叙述吞进公式。短符号和短式可以使用行内原生公式；推导、矩阵和长式独立成行，居中并留 3–6 pt 上下段距。行内排版不等于普通文本排版。
- LaTeX 或 UnicodeMath 可作为录入的中间格式，交付前必须转换为可编辑的原生公式并检查显示。公式截图、图片、普通文本框和未转换的源码均不能替代原生公式。
- 不用 Unicode 上下标、单字符分数、ASCII 运算符拼接或程序语法代替成稿数学符号。查找命中必须人工区分代码、路径和讲解反例，不能盲删字符。
- `sin`、`cos`、`exp`、`det`、`rank`、`max`、`cond` 等函数/运算名称正体，变量斜体，单位正体；向量/矩阵的粗体或箭头约定保持一致。
- 数学符号首次出现说明含义、单位和条件；超过 8 个符号时增加符号表。缩写较多时补缩写表。
- 长公式在合理运算位置分行并对齐，每步给出理由；独立式前后要有文字衔接。矩阵元素、行列数、增广分隔线和括号不得跨页断裂。
- 转换后重新提取和目视比较正文；重点检查公式前后的标点、说明与段落，避免转换工具合并文字。

## 4. 提示框与用户标记

新建提示默认只用以下 3 类；用户已有标记的保留规则见 [修改保留流程](revision-preservation.md)。

| 类别/样式 | 浅底纹 | 深色标签/左边框 | 含义 |
|---|---|---|---|
| 提示-重点 | FFF2CC | BF9000 | 重点、必须记住的结论 |
| 提示-易错 | FBE4E4 | C00000 | 陷阱、边界条件、资料错误 |
| 提示-方法 | DEEBF7 | 2E74B5 | 做题方法、检查技巧 |

整段提示采用段落底纹及 2.25–3 pt 左边框，并有“【重点】”等文字标签；不要用 1×1 表格做提示框，也不要只高亮标签而漏掉内容。

- 同类同色，颜色只作辅助，黑白打印也能靠标签理解。只列实际使用的图例。
- 每页通常 2–3 框以内；相邻且同义的提示可合并，不为追求密度删除用户标记，也不合并语义不同的提示。
- 必要的背景可用灰色说明样式，不额外制造一套字体色与底色组合编码。
- 强调用术语/结论关键词加粗，不把整段、整页都设为粗体；中文不用斜体。被用户单独标记的词，可保留专门字符样式。

## 5. 表格与图

- 表格适合对照、参数和数据；单元格约 40 字以上或多数格为长句时，优先拆成小标题/列表。真正的数学矩阵使用公式，不用普通表格冒充。
- 三线表或细网格，顶/底线约 1.5 pt、表头下线 0.75 pt，表头浅灰 F2F2F2 并加粗。文字左对齐、数字右对齐或小数点对齐，单位写表头。
- 列宽按内容分配、行高自动或最小值；重复跨页表头，禁止普通表行跨页拆开。缺失和不适用要区分表达，不能用空格掩盖数据缺失。
- 表题在上、图题在下；正文引用每个图表并解释关键结果。
- 图采用嵌入式放置、等比缩放、靠近首次引用。嵌入式和“上下型”是不同的布局选项，不将二者当成同义词。
- 外部工具绘制专业示意图再插入，避免大量浮动 Word 形状。截图 PNG、照片 JPG，支持时选矢量；屏幕至少 150 dpi、打印至少 300 dpi，图中文字不小于 7 pt。
- 图的字体/符号与正文一致，图例能解释颜色，灰度仍可辨；裁掉无用空白，不牺牲字的可读性。

## 6. 中文、数据与出处

- 中文句子用全角标点，英文/数学内部用半角；中英文、中文与数字/公式间统一留半角空格，全角标点旁不另加空格。
- 数字与单位间留空格；角度和百分号不留。范围用短横线，负数用数学减号；同一指标精度一致，说明舍入规则。
- 同一概念同一术语、同一符号同一含义；不要混用数学约定，例如置换矩阵在等式中位于不同侧时必须说明定义。
- 比率和百分数转换后再比较。例如 `0.5762（57.62%）` 与上界 `48.80（4880%）`；上界可能很保守，不能当作实际误差。
- 关键结果复算，并做代回、量纲、量级或边界检查。例题先核对数据，再写推导；不要编出无来源的精确数值。
- 资料注明文件名及 PDF 页码，必要时区分印刷页码；教材写作者/版次/页码，网络来源用标题、链接及访问日期。
- 自动转写、OCR、模糊手写内容和不可访问的数据要说明限制。未确认的结论写“待核实”，不把来源推测写成事实。

## 适用边界

本技能提供可复用的技术写作、Word 排版和文档修改保留规则，所需规范均包含在技能目录中，不依赖外部私人资料。具体文档的要求、模板和用户指令优先于默认参数。

归纳时将“全篇清格式”限定为完成标记保留后；将 Cambria Math 保留为默认数学字体，而不宣称 Word 只支持这一种数学字体；字体检查以实际渲染和用途为准，不仅凭 fontTable 声明或全选字体框。UI 路径和快捷键随版本可能不同，未验证的操作口诀不作为强制实现方式。

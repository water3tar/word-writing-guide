# Word 交付检查

交付前读取，按本次范围检查。只审阅时报告问题；已获准制作/修改时完成相应修复。用户标记保护优先于通用排版偏好。

## 1. 用户修改保留（旧稿必查）

- [ ] 基于用户指定的当前文件；有可用旧版才声称做过版本比较。
- [ ] 高亮、不同颜色、底纹、删除线、批注、修订和段落变化已检查。
- [ ] 修改清单每一项都有对应去向；含义不明确的标记仍保留。
- [ ] 用户删除的段落或同义内容没有重新出现；数字和公式没有退回旧值。
- [ ] 批注锚点、待解决内容和修订状态未被意外清空或改变。
- [ ] 升级后的样式仍表达原来的重点和范围，英文术语补充准确、不过量。
- [ ] 未改动范围内的正文、公式、图表和用户格式没有意外损失。

## 2. 内容与数学

- [ ] 技术小节的问题、条件、方法、例子和要点清楚；非技术文档没有被硬套结构。
- [ ] 关键公式与数据重新对照来源；至少抽查 2 个关键数字/例题，少于 2 个则检查全部。
- [ ] 例题包含结果和验算，推导不无理由跳步；量纲、量级、边界合理。
- [ ] 所有方程、等式、不等式和数学公式均为可编辑的 Word 原生公式，包括行内短式、独立公式和表格中的公式。
- [ ] 逐处核对简单式子也已转换，不能仅凭文档含有公式对象或公式总数就认定全篇合格。
- [ ] 原生公式中的分式、上下标、矩阵等使用真实数学结构，行列及元素正确；没有用图片、普通文本或未转换的源码代替公式。
- [ ] 搜索方括号/分号、Unicode 上下标、`½ ¼ ¾`、`^`/`_` 等线索，人工排除一行矩阵和假公式；合法代码/路径/原文反例保留。
- [ ] 函数名和单位正体、变量斜体；符号有定义、术语统一。
- [ ] 公式转换未吞入解释文字、丢掉标点或合并不应合并的段落。
- [ ] 比率/百分数、单位和有效数字一致，理论上界与实际结果明确区分。
- [ ] 引用可定位；OCR/转写/数据缺失等限制如实说明。

## 3. 样式、导航与视觉

- [ ] 正文/标题/表格/题注/页眉页脚的样式和主题一致；自动更新关闭。
- [ ] 正文与标题的西文 Arial、中文宋体，公式 Cambria Math；用户模板、代码等合理例外有明确用途。
- [ ] 提示框采用一致的浅底纹和左边框，有文字标签；图例无闲置类别。用户词级标记不强行扩大为整段。
- [ ] 标题无跳级和孤立页底标题；编号、例题、图表及交叉引用无断号/错指。
- [ ] 更新正文、页眉页脚等相关位置的域及整个目录，确认页码实际更新；仅设置“打开时更新”不等于已检查结果。
- [ ] 无连续空段落、空格拼接对齐或大量无意义留白；不靠缩小全部字体掩盖布局问题。
- [ ] 表头重复、表行不被无故拆断，列宽足够、数值对齐，无裁切文字。
- [ ] 图表题注位置正确，图不变形，正文引用并解释；矩阵/公式不跨页断裂。

## 4. 必须区分结构检查和视觉检查

1. 检查保存后的 DOCX 内容、样式、公式结构及评论/修订部件；必要时与修改前比较。
2. 用当前可用的文档渲染流程生成页面，逐页查看。配合 `documents` 技能时遵循其渲染要求；工具不可用时检查可用替代，如安装的 Word 导出 PDF，再检查 PDF 页面。
3. 查看所有页的公式、页顶页底、图表、题注和换页；编辑过的用户标记区域要特别核对。修复问题后重新检查受影响页。
4. 查看导出 PDF 的实际字体。Arial/SimSun/Cambria Math 及其正常粗斜体/子集名称符合默认；代码或特殊符号的额外字体应有明确来源。字体表中的声明本身不证明页面实际用了该字体。
5. 无法渲染或缺少字体时明确报告具体未完成项，不能用 XML 检查冒充“逐页看过”。

## 5. 文件与交付

- [ ] 大改保存新版本，原稿可恢复；文件名含主题、版本及日期。
- [ ] 默认 `.docx` + PDF，或遵循用户指定的交付格式；没有多余测试稿混进交付清单。
- [ ] 给出能打开的最终文件链接，简述改动、保留/升级的标记以及已做的验证。
- [ ] 必要的未决问题明确列出；没有声称做过实际上缺少条件的历史比较、计算或视觉检查。
